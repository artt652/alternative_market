# Личный маркет дополнений (home_market)

Модуль маркета дополнений для MajorDoMo — форк штатного `market` с упором на
надёжную работу на Android/Termux, офлайн-режим, установку из собственных
Git/архив-источников и аккуратный разбор установленных/системных модулей.

Имя модуля: `home_market` · Название в админке: **«Личный маркет дополнений»**

---

## Возможности

### Каталог и источники
- **Отказоустойчивость источников.** Каталог запрашивается по очереди с
  `connect.majordomohome.com` и `connect.smartliving.ru` (один и тот же сервис,
  разные домены). Принимается первый валидный JSON-ответ.
- **Офлайн-кеш.** Каждый успешный ответ сохраняется в
  `cms/market_cache/<md5(запрос)>.json`. Если недоступны все источники —
  отдаётся последняя локальная копия (каталог можно листать без интернета).
- **Доп. зеркала.** Можно добавить свои источники без правки кода:
  ```php
  // config.php
  Define('MARKET_MIRROR_HOSTS', 'https://ваш-хост/market/');
  ```
- **Авторизация connect.** Логин/пароль берутся из модуля `connect` — нужны для
  вкладки «Owned» (приобретённые) и скачивания платных/привязанных дополнений.

### Вкладки
- **Установлено** — установленные дополнения (из каталога connect и установленные
  локально/из архива).
- **Обновления** — только модули с доступным обновлением.
- **Owned** — приобретённые под вашим аккаунтом connect.
- **Все** — полный каталог.
- **<категории>** — категории каталога.
- **Custom** — только модули с собственным Git/архив URL (см. «Свой GIT»).
- **Системные** — базовые модули платформы (read-only: доступна только «История»,
  без установки/обновления/удаления).

### Карточка модуля
- **Бейдж источника:** `Connect` · `Git URL` · `Локально` · `Система`.
- **Кнопка «Источник»** — ссылка на репозиторий/страницу модуля (для GitHub —
  на страницу репозитория, а не на tar.gz).
- **«Обсуждение»** — ссылка на форум модуля (если задан `SUPPORT_URL`), для
  любых модулей (в т.ч. бесплатных).
- **«Купить»** — для платных модулей из каталога.
- **История** — список коммитов из GitHub-ленты, доступна и для неустановленных
  модулей. Версия определяется по sha последнего коммита; ветка по умолчанию
  берётся через `HEAD`/`commits.atom` (работает и для `master`, и для `main`).

### Свой Git / архив URL (custom-repository)
- Кнопка **«Свой GIT»** на карточке — привязать модулю ссылку на репозиторий или
  архив. Поддерживаются GitHub `repo`/`tree`/`commit`/`tag` и прямой `.tar.gz`.
- Привязанные модули обновляются из указанного источника и показываются на
  вкладке **Custom**.
- Ручная установка по ссылке — в шапке, блок **«Git / архив URL»**.

### Установка из архива
- Загрузка локального `.tgz`/`.tar.gz` в шапке («Добавить вручную»).
- Корректно обрабатываются **имена файлов с пробелами** и расширение `.tar.gz`
  (исправлены ошибки `Unpack failed!` и `Headers already sent`).
- Перед установкой пакет проверяется на структуру модуля
  (`modules/<module>/<module>.class.php`).

### Экспорт модуля
- Пункт **«Экспорт»** в меню карточки (для всех установленных, включая системные).
- Собирает `.tgz` со **всеми папками модуля** (`modules/<name>`,
  `templates/<name>` и прочие файлы из манифеста установки). Архив совместим с
  обратной установкой через маркет.

### Порядок в списке и дедупликация
- **Системные модули** выделены на отдельную вкладку и не засоряют «Установлено»/
  «Custom». Признак «установлен через маркет» — наличие манифеста
  `cms/modules_installed/<name>.files` или своего Git/URL.
- **Дубли реестра** (например, запись под именем архива `*-master`/`*_<timestamp>`
  при живом модуле) схлопываются по реальному модулю — он определяется по его
  собственному классу `modules/<X>/<X>.class.php` в манифесте. Удаляются только
  **строки реестра и осиротевшие файлы-списки `.files`** — файлы модулей не
  затрагиваются. Имя оставленной записи приводится к реальной папке, поэтому
  удаление снимает именно нужный модуль.

## Установка

**Способ 1 — через маркет.** «Добавить вручную» → загрузить `home_market.tgz`.

**Способ 2 — вручную** (рекомендуется при обновлении самого маркета):
```bash
HT=/data/data/com.termux/files/home/htdocs   # путь к htdocs
tar xzf home_market.tgz -C ~/
cp -r ~/home_market/modules/home_market   "$HT/modules/"
cp -r ~/home_market/templates/home_market "$HT/templates/"
cp -r ~/home_market/img                   "$HT/"      # иконка модуля
php -l "$HT/modules/home_market/home_market.class.php"
```
После установки откройте **Панель → Личный маркет дополнений**
(`panel/home_market.html`) и сделайте жёсткий refresh (обновлены версии CSS/JS).

### Структура пакета
```
home_market/
├── img/modules/home_market.png          # иконка модуля
├── modules/home_market/
│   ├── home_market.class.php            # логика модуля
│   ├── details.inc.php                  # детальный вид / история
│   ├── update_iframe.php                # установка/обновление (прогресс)
│   └── export.php                       # выгрузка модуля в .tgz
└── templates/home_market/
    ├── home_market.html                 # оболочка (шапка, вкладки, модалка)
    ├── list.html                        # карточки списка
    ├── details.html                     # история коммитов
    ├── home_market.css
    └── home_market.js
```

## Требования
- PHP 7.x/8.x (код проверялся на PHP 8).
- Доступный в системе `tar` (установка из архива и экспорт).
- Модуль `connect` с заданными логином/паролем — для приобретённых и платных
  дополнений (для бесплатных и установки по Git/URL не обязателен).

## Хранилище и совместимость
- Реестр дополнений — таблица `plugins` (общая со штатным `market`, если он тоже
  установлен).
- Кеш каталога — `cms/market_cache/`.
- Внешний сервис (`connect.*/market/`) не затрагивается — это удалённый API,
  а не часть модуля.

## Примечания
- Пометка `Connect`/`Локально` отражает, вернул ли сервис модуль в данный момент;
  офлайн или для снятых с публикации модулей возможна пометка «Локально».
- Системные/базовые модули недоступны для удаления из маркета намеренно.
